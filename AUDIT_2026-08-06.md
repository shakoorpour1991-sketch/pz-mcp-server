## 4. New findings (this pass)

**Analyzer logic bugs (read carefully — these are real, found by direct code trace):**

1. **MAJOR — `GLOBAL_VAR` false positives on every `local x = v` line.** `ModAnalyzer.ts:601-632`: local variables are registered into `globalVars` **only when `inStrictContext`** (i.e. only after a line containing `--strict`/`--strict-context` appears), but the "Potential global variable leak" warning fires unconditionally for any assignment whose name isn't in `globalVars`. In a normal mod file (no `--strict` marker) `globalVars` stays empty, so `local foo = 1` matches the assignment regex → spurious warning on correct Lua. Fix direction: register `local` declarations always (drop the strict-context gate), or only emit GLOBAL_VAR when a name is assigned without ever being declared local.
2. **MAJOR — `UNUSED_REQUIRE` is dead code; the warning can never fire.** `ModAnalyzer.ts:636-660`: `requiredModules` is populated from **all** `require()` calls in the content, then each require-line is checked with `!requiredModules.has(module)` — which is always false for a line that contains a `require` (its module was just collected in pass 1). Either implement the intended check (module required but never referenced as a symbol later) or remove the branch.

**Analyzer / DB minors:**

3. **MINOR — `checkLuaSyntax` balance checks are per-line, not per-file.** `ModAnalyzer.ts:482-506`: Lua commonly spans expressions across lines (`foo(\n  x\n)`); each line is checked in isolation → false "Unbalanced parentheses/brackets" warnings. The `!line.includes("--")` guard also skips any line containing a comment anywhere (even `x = f(  -- note`), masking real imbalance on that line.
4. **MINOR — vanilla balance baseline capped at 100 FTS rows.** `ModAnalyzer.ts:781-784`: `searchContent(keyword, {type:'item', limit:100})` then filters `properties.Type === category.type`. Large vanilla categories (Weapon/Armor have hundreds) are under-sampled → the "vanilla average" baseline is biased and the cap is undocumented. Fix direction: raise limit or query by category directly.
5. **MINOR — redundant duplicate condition.** `ModAnalyzer.ts:509-512`: `line.includes("Events.OnPreMapLoad.Add") && line.includes("Events.OnPreMapLoad.Add")` — same predicate twice. Harmless but dead code.
6. **MINOR — FTS indexes raw JSON for `properties_text`.** `DatabaseManager.ts:243/294`: `properties` and `properties_text` both store `JSON.stringify(item.properties)`; the FTS column tokenizes braces/quotes/colons, so searches can match JSON noise. Functionally OK (results are real), but a plain-text mirror would rank better. Low priority.
7. **MINOR — docs-vs-code: KB "YAML frontmatter" claim is wrong.** `docs/project-summary.md` says KB docs have "YAML frontmatter"; `KnowledgeBaseManager.ts:84-97` actually parses `# ` H1 for title and `> Source:` blockquote for source — no frontmatter handling. Fix the doc (or the parser, if frontmatter is intended).
8. **MINOR — Steam registry query still fails on this machine.** Test output shows `Failed to read Steam registry: Registry query failed` (warn, non-fatal; detection still works via hardcoded `D:\Games\ProjectZomboid` path). Audit #22's "resolved" was about the feature existing — the actual registry read errors here (likely HKCU key absent for the `reg query` user context). Cosmetic noise on every `parse_game_files` without explicit path.
