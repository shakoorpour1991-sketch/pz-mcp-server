## 2. Highest-severity findings (fix first)

**P1 — `node:sqlite` requires Node ≥ 22.5, but project claims Node 18/20**
- `DatabaseManager.ts:1` and `KnowledgeBaseManager.ts:1` import `node:sqlite` (added in Node 22.5).
- Verified live: `npx node@20` → `ERR_UNKNOWN_BUILTIN_MODULE`; `npx node@18` → same. Server cannot boot on Node 18/20.
- Yet: `package.json` engines `>=18.0.0`; README says "Node >= 18" and "VS C++ Build Tools required" (better-sqlite3 era — also false now); CI matrix `.github/workflows/ci.yml:13` runs Node 20.
- Fix direction (later): engines `>=22.5`, CI matrix `[22]` (or add a 24 job), README/AGENTS.md refresh.

**P2 — CI is red on the fork (all 3 runs since Aug 4)**
- GitHub API: runs 30904105195 / 30906012221 / 31041084241 — all `failure`.
- Latest (31041084241, head = master): `ci (22, ubuntu-latest)` failed at step **Run npm test**; the other three matrix jobs were cancelled.
- Root cause of the 22/ubuntu `npm test` failure: **Unknown — requires CI log access (log download needs a token)**. Not reproduced locally (Windows/22 passes). Candidates: jest `--experimental-vm-modules` on ubuntu, integration-test flake, fs/WAL timing.

**P3 — `analyze_mod` balance analysis pollutes the vanilla DB and compares wrong populations**
- `ModAnalyzer.analyzeBalance` → `parser.parseModDirectory(modPath)` inserts mod items into the **same `items` table as parsed game data** (`ModAnalyzer.ts:617`), then `getItemsByType('item')` (`:618`) returns **vanilla + mod mixed**. `itemCount`/`averageStats` are wrong, and vanilla items are compared against baselines that include themselves. Mod items persist until `clearDatabase()`.
- Fix direction: analyze against a temp DB (or namespace mod items), or diff before/after parse.
